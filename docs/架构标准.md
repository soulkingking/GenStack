# 架构标准

## 应用边界

`frontend/` 与 `backend/` 是独立应用。开发时分别运行，浏览器只请求相对路径
`/api`；Vite 将请求代理到 FastAPI。生产镜像把前端构建结果复制到 `/app/static`，
由 FastAPI 同源提供页面和 API。

## API

所有后端接口使用 `/api` 前缀。当前公开接口包括：

- `GET /api/health`
- `GET /api/meta`
- `GET /api/auth/session`
- `GET /api/auth/login`
- `POST /api/auth/token`
- `GET /api/current-user`

新增业务时保持路由、业务逻辑和持久化职责分离，禁止把复杂业务直接写进
`app/main.py`。

## 认证边界

GenStack 是第三方 OAuth2 客户端，使用授权码模式。React 只负责会话检查、识别
`code/state` 和控制跳转；FastAPI 保存 `client_secret`、校验 `state`、兑换 Token
并设置 HttpOnly Cookie。浏览器接口只返回布尔认证状态，不返回 Access Token。

第三方认证服务的 Token 控制器虽然同时接受 GET/POST，但本项目固定使用
`POST application/x-www-form-urlencoded`，防止密钥进入 URL 和访问日志。
`redirect_uri` 使用后端显式配置，不根据请求 Host 动态生成，并且必须与第三方认证服务
登记值完全一致。

当前 Cookie 直接承载第三方 Access Token。业务接口由 FastAPI 读取 Cookie，并通过
`app/clients/` 作为 BFF 调用远程服务，不能让 React 读取 Token。公共客户端统一处理
Bearer Header、超时、HTTP 状态和业务响应外壳，领域客户端负责接口地址和字段映射。
`GET /api/current-user` 仅返回显式白名单字段；远程 401/403 会清除 Cookie，其他远程失败
对外统一为 502。引入 Redis 或数据库后，可以把
Cookie 改为随机 Session ID，而不改变前端认证接口。

## 配置与数据

配置由 `backend/app/core/config.py` 统一读取。密钥不得写入仓库。运行时数据必须
写入 `data/`，容器部署必须挂载该目录。`DATABASE_URL` 只是未来持久化功能的配置
入口；当前应用不会连接数据库。

## 当前非目标

当前没有用户同步、权限模型、Refresh Token、主动登出、API Key、ORM 或数据库迁移。
Nacos 仅提供可选服务注册。引入以上能力前必须先定义真实接口和运行约束，并同步
更新本文档。
